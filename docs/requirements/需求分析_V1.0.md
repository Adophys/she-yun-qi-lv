## 1. 项目概述

### 1.1 项目背景

畲族是中国南方历史悠久的少数民族，拥有独特的语言、服饰（凤凰装）、纹样、音乐、饮食和手工艺文化。然而：

- 畲族文化**传播渠道有限**，年轻一代认知度低，文化传承面临断层风险；
- 现有畲族村落的文旅体验以**静态展陈为主**，缺乏互动性和趣味性，对年轻游客吸引力不足；
- 散落的文化元素（服饰、纹样、歌谣、工艺）**缺少数字化整合平台**，难以系统性了解。

**畲韵奇旅**以微信小程序为载体，通过「游戏化探索 + AR/NFC 交互 + 数字收藏」的方式，让用户（尤其是年轻人和研学群体）在玩乐中认识畲族文化，助力民族文化数字化保护与传播。

### 1.2 项目目标

| 目标 | 衡量指标 |
|---|---|
| 畲族文化科普传播 | 上线 3 个月内注册用户 ≥ 5000，图鉴卡片解锁 ≥ 20000 次 |
| 提升文旅体验 | 与 ≥ 1 个畲族村落/景区合作落地 AR/NFC 扫描点位 |
| 游戏化留存 | 次日留存率 ≥ 30%，平均单次使用时长 ≥ 8 分钟 |
| 内容可运营 | 管理端支持文化内容、关卡、成就的全流程配置，无需发版 |

### 1.3 项目定位

- **产品形态**：微信小程序（用户端）+ Web 管理后台（运营端）
- **目标平台**：微信小程序（iOS / Android）
- **商业模式**（比赛展示用）：文旅合作分成、研学课程定制、文创电商导流、政府文化项目补贴

## 2. 用户分析

### 2.1 目标用户群体

| 用户群体 | 特征 | 核心诉求 |
|---|---|---|
| 年轻游客（18-30 岁） | 到畲族村落旅游，习惯用小程序 | 有趣、能分享、拍照打卡 |
| 研学学生（8-16 岁） | 学校组织的文化研学活动 | 游戏化闯关、收集成就感 |
| 研学带队教师 | 组织学生活动，需要过程管理 | 任务进度可控、成果可展示 |
| 文化爱好者 | 对民族文化有主动兴趣 | 系统性、深度的文化内容 |
| 运营人员（管理端） | 村落/景区/项目方工作人员 | 内容上架、数据统计、用户管理 |

### 2.2 用户画像（示例）

**画像 A —— 大学生游客「小林」**
- 22 岁，和同学周末到景宁畲族村游玩；
- 看到村里的 NFC 点位海报，扫码进入小程序；
- 扫描后解锁「凤凰装」图鉴卡片，试玩换装给 IP 形象穿上凤凰装；
- 觉得有趣，分享到朋友圈。

**画像 B —— 研学学生「小吴」**
- 13 岁，参加学校组织的畲乡研学一日营；
- 全班按小组完成「章节探索」任务，扫描 5 个文化点位；
- 集齐纹样碎片完成凤凰拼图，获得电子成就勋章。

**画像 C —— 运营人员「兰姐」**
- 景区工作人员，负责文化内容维护；
- 通过管理后台上架新的图鉴卡片、配置 NFC 点位、查看扫码数据统计。

### 2.3 核心用户旅程

```
发现（线下海报/二维码/朋友分享）
  → 进入小程序（微信授权登录）
  → 村落主页（IP 形象、任务引导）
  → 章节探索（地图关卡）/ 到点位 AR/NFC 扫描
  → 解锁图鉴卡片（学习文化知识）
  → 换装/拼图等游戏化玩法
  → 成就与分享（朋友圈/好友）
  → 沉淀（收藏回顾、复访、新章节更新）
```

**商城实现方案（已确认：方案 A 真实微信支付）：**

| 方案 | 说明 | 状态 |
|---|---|---|
| **A. 真实微信支付** ✅ | 接入微信支付商户号（JSAPI/小程序支付），完成 下单→支付→发货→物流→收货/退款 完整闭环 | **已采纳** |
| B. 意向收集 | 商品展示 + 客服联系购买 | 未采纳（保留为降级预案） |
| C. 积分/碎片兑换 | 碎片兑换兑换券 | 未采纳（可后续叠加为营销玩法） |

**方案 A 前置条件（团队须尽早推进，周期约 2-4 周）：**

1. 主体资质：企业或个体工商户营业执照（学校/孵化器主体亦可）；
2. 小程序完成**微信认证**（个人主体小程序无法开通微信支付，需非个人主体）；
3. 开通**微信支付商户号**（mchid），完成结算账户验证；
4. 小程序端关联商户号（AppID 绑定 mchid），开通 JSAPI 支付；
5. 商户平台配置支付回调域名、APIv3 密钥、证书/私钥文件（部署到后端 secrets）；
6. 服务器域名需 ICP 备案（request 合法域名要求）。

**方案 A 支付流程约定：**

```
小程序端下单 → 后端创建订单(待付款) + 调用微信「统一下单」
→ 返回 wx.requestPayment 参数 → 用户支付
→ 微信异步回调(pay notify) → 后端验签+验金额 → 订单置为「已支付/待发货」
→ 管理端发货录入物流单号 → 用户确认收货 → 订单完成
（退款走微信退款 API，管理端发起，回调确认）
```

关键实现要求：
- 支付回调必须**验签（APIv3 平台证书）+ 校验订单金额 + 幂等处理**；
- 订单号全局唯一，30 分钟未支付自动关闭（延迟任务）；
- 库存在下单时预占、支付成功扣减、超时释放，防止超卖；
- 退款需管理端权限控制并保留操作日志。

### 3.4 功能依赖关系（关键路径）

```
微信登录(U-01) → 村落主页(H-01) → 章节探索(E-01/E-02)
                                  → 扫描(S-01/S-02) → 图鉴解锁(C-02/C-03)
```

**商城在 MVP 中的定位（方案 A 已确认）**：

- 商城开发与支付资质办理**并行推进**：M1 阶段完成商品浏览/购物车/下单页面与订单模型（支付按钮置灰或跳「即将开放」），同时办理微信认证与商户号；

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 |
|---|---|
| 小程序首屏加载 | ≤ 3 秒（微信性能评分达标） |
| API 平均响应时间 | ≤ 300ms（P95 ≤ 800ms） |
| 扫描识别到结果页 | ≤ 2 秒 |
| 并发支持 | 峰值 500 QPS（研学团体集中扫码场景） |
| 分页加载 | 列表类接口必须分页 |

### 4.2 安全需求

| 编号 | 需求 | 说明 |
|---|---|---|
| N-01 | 传输安全 | 全站 HTTPS，微信 request 合法域名白名单 |
| N-02 | 接口鉴权 | 用户端 Token 鉴权（JWT），管理端独立鉴权体系 |
| N-03 | 越权防护 | 用户只能访问自己的收藏/装扮/进度数据 |
| N-04 | 防刷 | 扫描/奖励接口幂等设计 + 频率限制 |
| N-05 | 数据备份 | 数据库每日备份，媒体文件异地备份 |

### 4.3 合规需求（小程序审核重点）

- **隐私协议**：收集微信头像、昵称、位置（AR 扫描）、收货地址前需用户明示同意（`privacy.js` 常量已规划协议文本位）；
- **用户协议**：条款页（terms 页面已规划）；
- **账号注销**：提供注销入口并真实删除/匿名化数据（U-04），已产生历史订单的用户需提示联系客服处理；
- **内容合规**：文化内容需事实准确，涉及民族文化的表述须经指导老师/文化顾问审核；
- **电商合规**（已确认方案 A 真实微信支付）：
  - 小程序需完成**企业/个体工商户**微信认证、开通微信支付商户号、补充《电商小程序合规指引》所需资质（营业执照、ICP 备案/增值电信业务许可证视经营范围）；
  - 支付能力开通前，商城支付入口以 feature flag 关闭，仅展示商品；
  - 商品信息必须真实，盲盒商品需公示款式概率；
- **未成年人**：不诱导消费，无社交风险功能；盲盒玩法需避免成瘾性设计。

### 4.4 兼容性与可用性

- 微信基础库 ≥ 2.30.0，覆盖 iOS / Android 主流机型；
- NFC 功能依赖手机硬件，**必须**提供二维码兜底（S-02）；
- 弱网环境（村落景区网络差）下提供重试与本地缓存。

## 8. 风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| NFC 线上点位铺设协调困难 | P0 功能无法演示 | 二维码作为等价兜底方案（S-02） |
| 文化内容准确性不足 | 审核风险、误导用户 | 邀请指导老师/畲族文化顾问审校内容 |
| 团队三人并行开发接口不一致 | 联调延期 | 以《接口契约》为唯一依据，先行评审 |
| 微信审核驳回（隐私/内容） | 上线延期 | 提前按 4.3 合规清单自查 |
| 研学团体集中扫码并发 | 系统卡顿 | 接口幂等 + 缓存 + 频控（N-04） |
| 商城真实支付资质办理延误 | 支付闭环无法上线 | 立即启动微信认证+商户号申请（周期2-4周）；未办齐时 feature flag 降级为意向收集（方案 B） |
| 盲盒合规风险 | 被指涉嫌赌博/诱导消费 | 公示概率、明确标价、不可变现、未成年人保护 |

## 9. 验收标准（MVP）

1. 新用户微信授权登录成功，进入村落主页看到 IP 形象；
2. 扫描一个测试二维码/NFC 点位，正确解锁对应图鉴卡片；
3. 图鉴页可查看已解锁卡片详情，未解锁卡片显示剪影；
4. 管理端可登录，可上架一张新图鉴卡片并在小程序端可见；
5. 管理端看板展示用户数与扫码统计；
6. 提供隐私协议、用户协议、注销入口，符合提审要求；
7. 商城入口可见，能浏览商品列表与详情；管理端可上架商品；
8. （M2 商城验收）完成一笔测试支付：下单 → 沙箱/真实支付 → 回调置为已支付 → 管理端发货 → 端内可见物流 → 确认收货/退款全链路可演示。
